6.1

Concepto y objetivos de protección y seguridad

¿Qué se busca proteger y por qué?

La protección es el conjunto de mecanismos que controla el acceso de usuarios, programas y procesos a los recursos de un sistema operativo. La seguridad reúne medidas para defender el sistema y sus datos frente a errores, accesos no autorizados y otras amenazas.

◈

Protección

Define quién puede utilizar un recurso y qué operaciones tiene permitido realizar, por ejemplo leer, modificar o ejecutar un archivo.

⬡

Seguridad

Busca preservar la información y mantener el sistema confiable frente a incidentes internos o externos.

Objetivos principales

  • Evitar que usuarios no autorizados utilicen los recursos.
  • Permitir que cada proceso acceda únicamente a los recursos necesarios.
  • Separar los mecanismos de protección de las políticas que establecen cómo se utilizan.
  • Conservar la confidencialidad, integridad y disponibilidad de la información.
Ejemplo: una cuenta de estudiante puede consultar un archivo compartido, pero no necesariamente modificarlo o eliminarlo.
6.2

Clasificación aplicada a la seguridad

La seguridad se organiza en diferentes ámbitos que trabajan en conjunto.

▣

Seguridad interna

Se relaciona con los controles incorporados al hardware y al sistema operativo para proteger los recursos. Incluye permisos, separación de procesos y controles de memoria.

HardwareSistema operativo
⌂

Seguridad externa

Protege el entorno donde se encuentra el equipo. Se divide principalmente en seguridad física y seguridad operacional.

InstalacionesProcedimientos
▤

Seguridad física

Protege los equipos contra daños, desastres e intrusos. Puede utilizar controles de acceso, detectores de humo, sensores de calor y cámaras.

⚙

Seguridad operacional

Consiste en las políticas y procedimientos que administra una organización para determinar quién puede acceder a los sistemas y cómo debe hacerlo.

6.3

Funciones del sistema de protección

Controles que evitan interferencias entre usuarios y procesos.

El sistema de protección establece límites para que los procesos utilicen los recursos de forma autorizada. Sus funciones principales incluyen:

01 · Protección de procesos del sistema

Evita que los procesos de usuario interfieran con los procesos esenciales del sistema operativo.

02 · Protección entre procesos

Impide que un proceso de usuario acceda o altere indebidamente los datos y actividades de otro.

03 · Protección de memoria

Delimita las áreas de memoria que puede utilizar cada proceso para evitar accesos indebidos.

04 · Protección de dispositivos

Controla el uso de dispositivos como discos, impresoras y unidades de almacenamiento.

6.4

Implantación de matrices de acceso

Una forma de representar los permisos de cada dominio sobre los recursos.

Una matriz de acceso representa los derechos que tienen los dominios o usuarios sobre los objetos del sistema. Las filas representan dominios, las columnas representan objetos y cada celda contiene las operaciones permitidas.

Dominio / ObjetoArchivo AArchivo BImpresora
AdministradorLeer / EscribirLeer / EscribirUsar
ProfesorLeer / EscribirLeerUsar
EstudianteLeerSin accesoUsar
¿Cómo se interpreta? Si la celda de Estudiante y Archivo A contiene «Leer», ese dominio puede consultar el archivo, pero no modificarlo.

Elementos de la matriz

  • Dominios: usuarios, procesos o grupos con determinados permisos.
  • Objetos: archivos, directorios, memoria o dispositivos.
  • Derechos: operaciones como leer, escribir, ejecutar o eliminar.

La política de seguridad determina cómo se llenan las celdas. La matriz también puede representar cambios de dominio, cuando un proceso pasa de un conjunto de permisos a otro.

6.5

Protección basada en el lenguaje

La seguridad también puede integrarse en los lenguajes de programación.

La protección basada en el lenguaje utiliza las características de un lenguaje de programación para establecer y comprobar restricciones de acceso. En lugar de depender únicamente del sistema operativo, parte de las reglas se expresa en el propio programa y puede verificarse durante la compilación o la ejecución.

Control de tipos

Evita operaciones incompatibles con el tipo de dato y reduce errores que podrían comprometer el funcionamiento del programa.

Encapsulamiento

Oculta los detalles internos de una estructura y permite acceder a sus datos mediante operaciones definidas.

Control de acceso

Modificadores como público, privado o protegido limitan qué partes del programa pueden utilizar determinados elementos.

Verificación

El compilador o el entorno de ejecución puede comprobar que el programa respete las reglas establecidas.

Ejemplo: una clase puede declarar un dato como privado para impedir que otras partes del programa lo modifiquen directamente. El acceso se realiza mediante métodos autorizados.
6.6

Validación y amenazas al sistema

Comprobar identidades y reconocer posibles riesgos.

Validación y autenticación

La validación permite comprobar la identidad de un usuario y determinar si tiene autorización para utilizar un recurso. Entre los métodos de autenticación se encuentran:

Algo que sabes

Contraseña o PIN.

Algo que tienes

Tarjeta o dispositivo de autenticación.

Algo que eres

Huella digital o reconocimiento facial.

Las contraseñas deben ser difíciles de adivinar, no deben compartirse y conviene utilizar mecanismos adicionales de autenticación. Los sistemas también pueden limitar los intentos fallidos y almacenar las contraseñas mediante funciones de hash diseñadas para ese propósito.

Tipos de amenazas

Interrupción

Un recurso deja de estar disponible o queda inutilizable. Afecta la disponibilidad.

Intercepción

Una persona no autorizada obtiene acceso a información. Afecta la confidencialidad.

Modificación

Se altera información o recursos sin autorización. Afecta la integridad.

Fabricación

Se introducen datos, mensajes o elementos falsos en el sistema. Afecta la autenticidad e integridad.

Ejemplos de amenazas de software

  • Virus: código malicioso que puede infectar otros archivos o programas.
  • Gusano: programa que puede propagarse entre equipos a través de redes.
  • Caballo de Troya: programa que aparenta ser legítimo, pero realiza acciones no autorizadas.
  • Puerta trasera: mecanismo oculto que permite evadir los controles normales de acceso.
  • Bomba lógica: código que activa una acción cuando se cumple una condición determinada.
Medidas preventivas: mantener el sistema actualizado, utilizar autenticación robusta, realizar copias de seguridad y revisar los registros de actividad.
6.7

Cifrado

Convertir información legible en datos protegidos.

El cifrado es un proceso que transforma información legible, llamada texto plano, en información codificada o texto cifrado mediante un algoritmo y una clave. Su propósito es impedir que personas no autorizadas comprendan los datos.

Texto original

El mensaje o archivo que se desea proteger.

Algoritmo + clave

El proceso matemático transforma los datos.

Texto cifrado

El resultado solo puede recuperarse con la clave correspondiente.

Tipos de cifrado

Cifrado simétrico

Utiliza la misma clave para cifrar y descifrar. Es eficiente para proteger grandes cantidades de información. Ejemplo: AES.

Una clave compartida

Cifrado asimétrico

Utiliza un par de claves relacionadas: una pública y otra privada. Una puede utilizarse para cifrar y la otra para descifrar, según el esquema empleado.

Clave públicaClave privada

¿Dónde se utiliza?

  • En conexiones seguras entre navegadores y sitios web.
  • En archivos y discos para proteger información almacenada.
  • En aplicaciones de mensajería para proteger comunicaciones.
  • En sistemas de autenticación y protección de datos.
Importante: el cifrado protege la confidencialidad, pero debe combinarse con controles de acceso, gestión segura de claves y otras medidas para ofrecer una protección completa.
